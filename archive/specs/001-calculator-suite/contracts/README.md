# API Contracts: Calculator Suite  -  WebCalc MVP

## Overview

The WebCalc platform exposes three interfaces:

1. **Embed Widget** (iframe)  -  third-party sites embed calculators
2. **REST API** (v1)  -  developers access calculator engines programmatically
3. **Web App** (browser)  -  end users interact via the web interface

This document defines the contracts for the REST API and Embed Widget.

---

## 1. REST API v1

**Base URL**: `/api/v1`

**Authentication**: Bearer token in `Authorization` header.
API keys are generated per-user in account settings.

**Rate Limits**:
- Free tier: 100 requests/hour
- Pro tier: 1,000 requests/hour
- Enterprise: 10,000 requests/hour (custom)

**Content-Type**: `application/json`

### 1.1 Calculate

Perform a calculation using a specific calculator engine.

```
POST /api/v1/calculators/:slug/calculate
```

**Request**:

```json
{
  "inputs": {
    "customers": 1000,
    "arpu": 50,
    "churnRate": 5
  }
}
```

**Success Response** (200):

```json
{
  "calculator": "mrr-calculator",
  "formula": "MRR = Number of Customers × Average Revenue Per Customer",
  "inputs": {
    "customers": 1000,
    "arpu": 50
  },
  "outputs": {
    "mrr": {
      "value": 50000,
      "label": "Monthly Recurring Revenue",
      "format": "currency"
    },
    "arr": {
      "value": 600000,
      "label": "Annual Recurring Revenue",
      "format": "currency"
    }
  },
  "meta": {
    "requestId": "calc_abc123",
    "timestamp": "2026-05-21T12:00:00Z"
  }
}
```

**Error Responses**:

| Status | Code | Description |
|--------|------|-------------|
| 400 | INVALID_INPUTS | One or more inputs failed validation |
| 401 | UNAUTHORIZED | Missing or invalid API key |
| 404 | NOT_FOUND | Calculator slug not found |
| 429 | RATE_LIMITED | Rate limit exceeded |

**Validation Error Example** (400):

```json
{
  "error": "INVALID_INPUTS",
  "message": "One or more inputs are invalid",
  "details": [
    {
      "input": "churnRate",
      "error": "must be between 0 and 100",
      "received": -5
    }
  ]
}
```

## 2. Embed Widget

### 2.1 Embed Snippet

Third-party sites embed calculators via an iframe snippet generated by the
platform.

**Generated Snippet**:

```html
<iframe
  src="https://webcalc.io/embed/mrr-calculator"
  width="100%"
  height="480"
  frameborder="0"
  style="border: none; max-width: 600px; margin: 0 auto; display: block;"
  title="MRR Calculator by WebCalc">
</iframe>
```

### 2.2 Embed Page Contract

The embed route (`/embed/:slug`) delivers a lightweight page with:

| Element | Required | Description |
|---------|----------|-------------|
| Calculator widget | yes | Fully functional calculator (same engine as main site) |
| Input fields | yes | All inputs defined in CalculatorConfig |
| Results display | yes | All outputs defined in CalculatorConfig |
| Attribution link | yes | "Powered by WebCalc" link in footer |
| Styling | yes | Responsive, container-width adapts automatically |
| Navigation | no | No site nav, no sidebar, no ads |

**Communication**: The embed page communicates with the parent site via
`postMessage` API for optional cross-frame interaction.

```
// Parent → iframe
{ type: "SET_INPUTS", payload: { customers: 1000, arpu: 50 } }

// iframe → parent
{ type: "CALCULATION_RESULT", payload: { mrr: 50000, arr: 600000 } }
{ type: "EMBED_LOADED", payload: { calculatorSlug: "mrr-calculator" } }
```

### 2.3 Embed Tracking

When an embed page loads, the platform records:
- Origin URL (from `Referer` header or `postMessage` origin)
- Calculator slug
- Timestamp
- Calculation count (incremented on each calculate action)

## 3. URL State Contract

Calculator state is encoded in URL searchParams. This applies to both the web
app and the embed widget (for initial state via parent page).

### Format

```
/[category]/[slug]?[inputId1]=[value1]&[inputId2]=[value2]
```

### Example

```
/saas-metrics/mrr-calculator?customers=1000&arpu=50
```

### Rules
- All input values are URL-encoded
- Boolean values: `true` / `false`
- Missing optional inputs use the CalculatorConfig default value
- Invalid or missing required inputs: calculator shows default state
- Canonical URL (for SEO) is always the base page without params
