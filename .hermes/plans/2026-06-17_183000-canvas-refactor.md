# Canvas Page Refactoring Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Rewrite the Canvas workspace (`/canvas` route) so nodes connect via cables, values propagate through a reactive graph engine, and the UI reflects live computation results — currently the workspace dispatches document-level CustomEvents that are consumed by a parallel, broken execution engine inside `SaaSCanvas.tsx`, with no wiring between the two.

**Architecture:** Consolidate around a single clean architecture:
1. **Graph Engine** (`canvas/engine/graph.ts`): Already exists — pure TS, proper Kahn's algorithm, cycle detection, propagation.
2. **React Context** (`components/canvas/CanvasContext.tsx`): Becomes the single state machine — nodes, edges, execution results.
3. **Workspace** (`CanvasWorkspace.tsx`): Subscribes to context, wires drag/edit → context updates.
4. **Canvas Renderer** (`SaaSCanvas.tsx`): Renders react-flow canvas using context state; subscribes to execution results.
5. **Nodes** (`canvas/nodes/`): Single source of truth for node components — imported by SaaSCanvas only.
6. **Storage**: Context persists nodes/edges to localStorage; engine reads from context.

**Tech Stack:** Next.js 16, React 19, `@xyflow/react@^12.11.0`, TypeScript strict mode.

## Refactoring Approach

### Phase 0: Consolidate Architecture (No functional changes)

**Goal:** Establish the single data flow before any behavioral changes.

#### Task 0.1: Expand CanvasContext to own all state

**Files:**
- Modify: `components/canvas/CanvasContext.tsx`

**Objective:** CanvasContext holds `{ nodes, edges, activeSlug, showFullscreen }` and exposes `setNodes`, `setEdges` functions.

**Step 1: Replace context interface**

Current `CanvasContextValue`:
```ts
{ activeSlug, setActiveSlug, showFullscreen, setShowFullscreen }
```

New `CanvasContextValue`:
```ts
{
  nodes: CanvasCalculationNode[],
  edges: CableEdge[],
  activeSlug: string | null,
  showFullscreen: boolean,
  setNodes: (nodes: CanvasCalculationNode[]) => void,
  setEdges: (edges: CableEdge[]) => void,
  setActiveSlug: (slug: string | null) => void,
  setShowFullscreen: (show: boolean) => void,
  addNode: (slug: string, position: {x: number, y: number}) => void,
  deleteNode: (nodeId: string) => void,
  updateNodeInput: (nodeId: string, inputId: string, value: number) => void,
  executeAll: () => void,
}
```

**Step 2:** Use `useReducer` for nodes and edges state (not separate `useState` calls). This gives atomic updates needed for execution cycles.

**Step 3:** Implement `addNode()` — clones from `buildNodeFromSlug(slug, position)` or generates new ID.

**Step 4:** Implement `deleteNode()` — removes node and all connected edges.

**Step 5:** Implement `updateNodeInput()` — updates a node's input value and invalidates downstream execution.

**Step 6:** Implement `executeAll()` — calls graph engine, updates node results and cable values.

**Step 7:** Save to localStorage after every state change (debounced).

### Phase 1: Wire CanvasWorkspace to Context (Stateful, no execution yet)

**Files:**
- Modify: `components/canvas/CanvasWorkspace.tsx`

**Objective:** Replace the document-level CustomEvent bus with CanvasContext calls.

**Step 1: Remove all `document.dispatchEvent()` calls**

Delete these dispatches from CanvasWorkspace:
- `"canvas:addNode"` (→ call `context.addNode(slug, position)`)
- `"canvas:deleteNode"` (→ call `context.deleteNode(nodeId)`)
- `"canvas:nodeInputChange"` (→ call `context.updateNodeInput(nodeId, inputId, value)`)

**Step 2: Remove `window.addEventListener("canvas:...")` handlers from page.tsx**

These are no longer needed — SaaSCanvas will read directly from CanvasContext.

**Step 3: Wire node drag to context state**

On `onNodeDragStop`:
```ts
context.setNodes(nodes.map(n => n.id === id ? { ...n, position } : n))
```

**Step 4: Wire connection events to context state**

On `onConnect`:
```ts
const edge = buildCableEdge(source, target, sourceHandle, targetHandle)
context.setEdges(edges => [...edges, edge])
```

**Step 5: Wire delete button clicks directly to context**

The `handleClick` on CanvasWorkspace (not nodes) opens the fullscreen panel:
```ts
context.setActiveSlug(slug)
context.setShowFullscreen(true)
```

**Step 6:** Remove localStorage save/load — context will handle persistence.

### Phase 2: Rewrite SaaSCanvas as a Pure Context Consumer (Stateless Renderer)

**Files:**
- Rewrite: `components/canvas/SaaSCanvas.tsx`

**Objective:** SaaSCanvas subscribes to CanvasContext and re-renders. It does NOT manage nodes, edges, or execution state — that's context's job.

**Step 1: Remove all internal state (`useState` for nodes/edges)**

Current SaaSCanvas has its own `useState` for nodes, edges, execution state. All of this moves to CanvasContext.

**Step 2: Read from context in `useEffect` + `useSyncExternalStore` (or just subscribe via `useContext`)**

```tsx
const { nodes, edges } = useWorkspace()
```

**Step 3: Wire react-flow callbacks to context dispatchers**

- `onNodesChange`: → `context.setNodes` (drag, select)
- `onEdgesChange`: → `context.setEdges` (reconnect cable)
- `onConnect`: → call SaaSCanvas method that calls `context.setEdges(...)`
- `onNodeClick`: (on node itself, not workspace) → `context.setActiveSlug(node.slug)`

**Step 4: Execute-on-state-change pattern**

```tsx
const { nodes, edges, executeAll } = useWorkspace()

// Auto-execute when nodes or cables change
useEffect(() => {
  executeAll()
}, [nodes, edges]) // CanvasContext.executeAll reads from context state
```

**Step 5: Remove the stale `executeGraph()` function entirely.** It's imported from `graphEngine.ts` but doesn't match the context data shape. The execution logic comes from CanvasContext now.

**Step 6: Wire node re-rendering to `executeAll` results.** Each node's `data.result` should update when execution completes, so the skeuomorphic nodes show live computed values.

### Phase 3: Use `canvas/engine/graph.ts` as the Execution Engine

**Files:**
- Modify: `components/canvas/CanvasContext.tsx` (add import)

**Objective:** The clean graph engine at `canvas/engine/graph.ts` is the actual execution logic. Wire it through CanvasContext.

**Step 1: Convert graphEngine.ts types to CableEdge-compatible format**

`canvas/engine/graph.ts` defines `GraphEngine`, `GraphState`, `ExecutionResult`. CanvasContext maps:
- `graph.nodes` (Map<string, GraphEngine>) → `context.nodes` (CanvasCalculationNode[])
- `graph.edges` (GraphEdge[]) → `context.edges` (CableEdge[])

**Step 2: Implement `executeAll()` in CanvasContext**

```ts
function executeAll(): void {
  const engineMap = new Map<string, GraphEngine>()
  for (const node of nodes) {
    const engineMapEntry = new GraphEngine({ ... }, ...)
    engineMap.set(node.id, engineMapEntry)
  }
  const graph: GraphState = { nodes: engineMap, edges: canvasEdgesToEngineEdges() }

  const result = executeGraph(graph, (slug, inputs) => engines[slug](inputs))

  // Update nodes with execution results
  if (result.updatedNodes) {
    setNodes(nodes => nodes.map(n => {
      if (!result.updatedNodes?.includes(n.id)) return n
      // Update node.data.result and data.status
      return { ...n, data: { ...n.data, result: <computed>, status: "ready" } }
    }))
  }
}
```

**Step 3: Wire cable values through `executeAll`.** After execution, propagate `cableValues` back to edge data:
```ts
setEdges(edges => edges.map(e => {
  const val = cableValues.get(e.id)
  return val !== undefined ? { ...e, data: { ...e.data, value: val } } : e
}))
```

## Risks and Tradeoffs

| Risk | Mitigation |
|------|-----------|
| `@xyflow/react@^12.11.0` API may differ from existing SaaSCanvas code | Check `node_modules/@xyflow/react/dist/index.d.ts` for exact types before coding |
| `graphEngine.ts` uses different types (GraphEngine, GraphState) than CanvasCalculationNode | Write a small adapter in CanvasContext; don't modify graphEngine.ts (pure TS) |
| 75 calculators × grid layout could be slow on initial render | Use lazy rendering: only render nodes in viewport (xyflow's `onViewportChange`); don't call `buildAllNodes()` |
| Circular references through node data (config → inputs → outputs) may cause JSON.stringify for localStorage | Deep-clone before saving; use structuredClone or manual serialization |
| Removing CustomEvent bus means any external code using `window.dispatchEvent("canvas:...")` breaks | No external consumers exist — this was an internal pattern only used by CanvasWorkspace + SaaSCanvas |

## Open Questions

1. **Should we use `react-flow` v12's built-in Edge types or keep the custom CablePatchEdge?** The custom edge has brand colors (teal cable aesthetic). Recommendation: keep custom `edgeTypes` map but render it inline.

2. **Should node dragging trigger execution or is that manual?** Recommendation: make execution **manual** — a button "Run All" in the toolbar. Auto-execution on every drag causes thrashing with 75 calculators.

3. **Can we connect any calculator output to any input, or only semantically matching ones?** Recommendation: allow all connections (freeform), but add visual indicators (warning) for mismatched types.

4. **localStorage limit (~5MB):** If users save 75 nodes × edges, localStorage could fill up. Mitigation: use IndexedDB (via `idb-keyval`) or warn users before saving large workspaces.
